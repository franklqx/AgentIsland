## P1014-04 · HUNG 前写一行路径容量

**PROPOSAL · pending CEO adoption**

证据：开盘时 3 腿 × t1$ 下限 $40 = $120，低于 $200，所以只贴着下限的一天到不了目标。R2 书面 t1$ $49.92。即使打到，差额仍是 $150.08，剩下最多 2 腿，平均要 $75.04。单笔计划亏损 ≤$50 且 t1 恰好 1.5× 止损时，单笔 t1$ 是 $75，三腿打满是 $225。$75.04 比这个 $75 高 $0.04。R2 又写在 12:35、成交在 13:15，主窗口已经过了。覆盖令的 1.2× 三腿上限是 $180，今天实际用了 1.50。

改动：写 HUNG 之前在同一条记录里加一行。1.5× 是下限，不是 t1$ 的天花板；这行只比较「剩余腿在下限边界上的平均要求」和「$50 / 剩余额度所能支持的 1.5×」。

```
room = 100 + min(0, realized+unrealized)   # 当日已有盈利不把亏损额度撑过 $100
per_leg_loss_cap = min(room, 50)
boundary_t1$ = 1.5 × per_leg_loss_cap
slots_left = 0 若时刻 ≥ 15:00，否则 max(0, 3 - legs_filled)
gap = 200 - qualified
need_avg = gap / slots_left                 # slots_left = 0 且 gap > 0：不除，标 WINDOW_CLOSED
gap_if_this_hits = gap - this_planned_t1$
slots_after = max(0, slots_left - 1)
need_avg_after = gap_if_this_hits / slots_after   # slots_after = 0 且差额仍 >0：不除，标 THIS_LEG_LEAVES_GAP
```

- `slots_left = 0` 且 `gap > 0`：标记 `WINDOW_CLOSED`。
- `slots_after = 0` 且 `gap_if_this_hits > 0`：标记 `THIS_LEG_LEAVES_GAP`。
- `need_avg_after > boundary_t1$`：标记 `NEED_AVG_ABOVE_CAP`。含义是，这一腿若打到书面 t1，后面每腿都要高于「亏损上限 × 1.5」的平均数，才过得了 $200。
- 写入时刻 ≥ 11:30 且 < 15:00：另标 `LATE_WINDOW`。
- 按今天 12:35 的 R2 复算：`room=100`，`boundary_t1$=75`，`this_planned_t1$=49.92`，`gap_if_this_hits=150.08`，`slots_after=2`，`need_avg_after=75.04`。标记 `NEED_AVG_ABOVE_CAP` 与 `LATE_WINDOW`。差额只比边界高 $0.04；真正吃掉当天的是主窗口已过，以及之后的止损落在 15:00 之后。
- 这些标记只留在记录上。后面的扫描继续找仍能过门的候选。候选的 t1$ 可以高于 $40，只要计划亏损仍 ≤ `per_leg_loss_cap`、t1 仍 ≥ 1.5× 止损。找不到，当天就 MISS。
- 这行不授权第 4 腿，不授权把 1.5× 降到 1.2，不授权 t1$ 低于 $40，不授权计划亏损高于 `per_leg_loss_cap`，不授权 15:00 后开新仓，也不授权为了抬高 t1$ 去加大股数。
